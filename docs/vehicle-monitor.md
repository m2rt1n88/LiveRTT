# 整车状态监视

当前构型系统已支持可编辑关节树和可变轮组；新增字段、模板切换及扩展方法见 [构型模板与扩展](mechanism-configuration.md)。下文常规双轴 / 四轮字段继续兼容。

左侧「整车状态」将云台和底盘合成一张斜视图，用于对照电机反馈所还原的姿态与控制目标，并观察底盘旋转时云台的补偿。绿色实线是反馈，橙色虚线是目标；底盘按航向转动，云台同时叠加 Yaw / Pitch。支持 Mecanum 与四轮 X 型 Omni，六个电机均可悬停、键盘聚焦或点击固定数据窗。

首次升级后需重启 LiveRTT 的 Python 服务再刷新网页，后端才能保存新增的整车配置字段。已有 ELF 配置会补齐整车默认设置，模块默认关闭。

## 配置与使用

1. 加载对应 ELF，进入「整车状态」并启用。
2. 展开云台 / 底盘构型设置，绑定 Yaw、Pitch 和 FL / FR / BL / BR 六个电机，核对方向、额外减速比、零点与轮径 / 轴距。这里与原云台 / 底盘页面共用同一份配置，可直接编辑，不必重复填写。
3. 若使用 IMU 或程序内实测量，在共享的「自定义变量」中选择已选字段；顶部「自定义变量绑定」可以添加新的普通变量，并绑定可选的底盘目标航向。
4. 选择云台 Yaw 的参考系，连接 SWD、确认固件版本并开始采集。

整车开关独立：无需开启电机、云台或底盘监视页，也能采集所需六电机。多个模块使用相同电机时按路径去重，合计最多 64 个。单独切换其他模块开关不改变整车历史；修改共享绑定、构型或标定时清空受影响的整车历史和相对航向，防止混用数据。

## 参考系与目标

默认「相对底盘」适用于电机编码器：`最终 Yaw = 底盘航向 + 云台相对 Yaw`。反馈和目标分别合成，显示最终瞄向的最短 Yaw 误差、Pitch 误差，以及两个三维指向向量的夹角。

使用已转换到世界坐标的 IMU Yaw 时，选择「世界坐标」：最终 Yaw 直接使用该变量，不重复叠加底盘航向。反馈与目标必须在同一参考系；底盘 heading 也必须与 IMU 对齐航向零点。缺少对齐的实测底盘 heading 时，图中底盘用灰色参考结构表示，并提示参考系未对齐。Pitch 假定底盘水平。

底盘反馈优先使用 `modules.chassis.bindings.heading`。有绑定但读取失败时显示缺失，不退回轮速积分。未绑定时使用底盘角速度积分，从首次有效样本的 0° 开始建立相对航向；角速度可以来自已绑定实测变量，或四轮在线时的理想无滑移推算。

底盘目标航向可由 `modules.vehicle.bindings.headingTarget` 显式绑定，变量需同时列在 `watches` 中。未绑定时积分指令角速度，初始航向与当时反馈航向相同；缺少指令时保持目标缺失。云台目标沿用各轴实际控制模式或显式变量绑定；速度 / 电流模式不冒充角度目标。图中不积分平移位置。

## 补偿对照与数据质量

底盘 vx / vy / vt 遵循嵌入式仓库：向右 / 向前 / 顺时针为正；航向和校准后的云台 Yaw 统一为逆时针正。相对底盘参考系下：`合成瞄向角速度 = −底盘 vt + 云台相对角速度`。例如底盘 vt=+20°/s 顺时针，云台 +20°/s 逆时针，最终瞄向角速度接近 0。补偿读数和趋势先将底盘取负，统一为逆时针正。目标瞄向固定时，这个残差有助于排查补偿符号、比例和响应滞后；目标本身在运动时，残差不应强制为零。页面保留底盘航向、最终瞄向、指向误差和补偿角速度四组趋势，以及各电机在线 / 使能 / 输出 / 故障事件。趋势保留输入原值与积分角，原始角度变量跨 ±π 换边时可能产生图中跳变，最短角误差仍按环绕计算。

Yaw 使用水平转盘与平面指针，Pitch 为横向转轴。图内「Yaw 俯视方向盘」中蓝箭头是车头、绿箭头是当前瞄向、橙虚线是目标；下方显示相对车头左 / 右转的角度。Omni 四轮方向与底盘页共用，后轮标为 BL / BR。

积分使用采样时间与相邻角速度的梯形积分。暂停、角速度缺失、离线导致推算失败、时间倒退或相邻样本超过 1 秒时，中断的积分轨迹变为缺失，不跨空白外推，也不自动重新拼接。点击「重置相对航向 / 开始新的对照」后从新样本重建原点。实测航向与显式目标绑定不依赖积分连续性；暂停时图和数据窗显示带时间的历史值。

本监视采用水平底盘与双轴机构模型。仅凭这些电机不能测出整车真实 roll / 底盘 pitch、打滑、绝对位置或地理航向；相对积分会受轮径、轴距、标定和滑移误差影响。需要真实车体姿态时应绑定同参考系的 IMU 等实测变量。SWD 多字段也不是控制周期原子快照，偏差提示用于辅助定位，不自动判定固件控制正确或错误。

## 配置文件

沿用 JSON v2，新增以下模块；不复制原有电机映射：

```json
"vehicle": {
  "enabled": false,
  "bindings": {"headingTarget": ""},
  "angleUnit": "rad",
  "gimbalFrame": "body"
}
```

`gimbalFrame` 可选 `body` / `world`。目标航向的单位优先使用 `watches.unit`，为空时采用整车 `angleUnit`（`rad` / `deg`）；其他字段仍采用原模块的单位和倍率。开关与参考系按 ELF 保存，积分原点和姿态历史不保存到配置。完整空模板见 [motion-profile.json](examples/motion-profile.json)。

## 合成数据验证

运行 `python tests/manual_motion_server.py --port 18769 --scenario compensation --layout omni`，在测试端口加载「图形回归 / 合成数据，非实车」，连接测试替身并采集。该场景提供 vt=+0.2375 rad/s 顺时针底盘旋转及 Yaw=+0.2375 rad/s 逆时针云台补偿，叠加小幅跟踪误差；不会连接真实探针。配置保存在 `tests/.runtime/motion-fixture`，与正式 `data` 分开。
